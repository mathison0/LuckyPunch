# 2026 CSE 교류전 AI 부문 공식 가이드 기준

확인일: 2026-09-04 (Asia/Seoul)

이 문서는 shaims 참가자 가이드에서 직접 확인한 내용을 요약한 것이다. 전략 메모와
엔진 분석이 섞여 있는 `CLAUDE.md`와 달리, 공식 가이드에 실제로 적힌 요구사항과
주의사항만 기록한다.

가이드는 로그인 후 열람할 수 있고 추후 갱신될 수 있다. 대회 당일에는 원문을 다시
확인해야 한다.

## 제출 형식

- JavaScript 또는 Python 파일 하나를 제출한다.
- 여러 파일로 나누거나 `import`로 다른 제출 파일을 불러올 수 없다.
- 파일 크기는 4MB 이하여야 한다.
- 기본 파일명 형식은 `<팀명>_v<버전>.<js|py>`이다.
- shaims 제출 페이지에서는 업로드한 파일을 사이트가 규약에 맞게 자동 저장하므로,
  업로드 전에 파일명을 직접 맞출 필요는 없다.
- 로컬 `src/code-here/`에서 시험할 때는 파일명 형식을 지켜야 봇 설정 UI에 나타난다.
- shaims에 여러 번 제출할 수 있으며 각 제출은 새 버전으로 기록된다.

## JavaScript 봇 계약

- 파일 최상위에 `function decide(snapshot)`이 정의되어 있어야 한다.
- 헬퍼 함수, 상수, 전역 상태를 함께 정의할 수 있다.
- 파일은 매치 시작 시 한 번 실행되고, 최상위 변수는 tick 사이에 유지된다.
- `decide`는 `{ x, y, hit }` 객체를 반환해야 한다.
  - `x`: `-1`, `0`, `1`
  - `y`: `-1`, `0`, `1`
  - `hit`: `0`, `1`
- 필드 누락, 범위 밖 값, `undefined`, 예외는 해당 tick만 무입력으로 처리된다.
- 같은 봇이 LEFT와 RIGHT에 배치되어도 서로 다른 Worker에서 독립적으로 실행된다.

## 실행 시간

- 기본 게임 속도는 25 FPS이며 한 프레임은 40ms이다.
- 현재 기본 봇 결정 주기는 3프레임, 즉 120ms이다.
- `decide`는 120ms 안에 반환하는 것이 목표다.
- 360ms를 넘긴 응답은 폐기되고 해당 tick은 무입력으로 처리된다.
- 15 tick 연속 hard timeout이면 Worker를 재시작하며 전역 상태가 초기화된다.
- 파일 로드 초기화는 60초 안에 완료되어야 한다.

## `config.tickFrameGroupSize`

- `config.tickFrameGroupSize`는 한 bot tick에 묶이는 게임 프레임 수다.
- 현재 기본값은 `3`이다.
- 공식 API 문서는 이 값이 대회 준비 중 조정될 수 있으므로 하드코딩하지 말고
  스냅샷에서 읽으라고 안내한다.
- 실제 경과 시간은 `tick * 40 * config.tickFrameGroupSize`로 계산한다.

이 항목은 `/guide/rules`의 필수·파일 크기·시간 예산 목록이 아니라 `/guide/api`의
`config` 설명에 있다. 따라서 부정행위 조항은 아니지만 공식 기술 가이드 준수 여부를
검토할 때는 적용해야 한다.

## JavaScript 사용 범위

- 표준 JavaScript 전역(`Math`, `Date`, `JSON`, `Array`, `Map`, `Set`, `RegExp`,
  `console.log` 등)을 사용할 수 있다.
- `import`, `require`, `fetch`/XHR, DOM의 `window`·`document`, 새 Worker 생성은
  사용할 수 없다.
- 봇은 독립된 Web Worker 안에서 실행된다.
- 매 tick 로그를 출력하면 브라우저가 느려질 수 있으므로 로그는 카운터로 제한한다.

## 스냅샷 사용 주의사항

- 같은 파일이 어느 진영에도 배치될 수 있으므로 `side`를 확인해야 한다.
- `expectedLandingPointX`는 현재 순간의 예상값이므로 매 tick 새로 읽는다.
- `meta.score.self`와 `meta.score.opp`는 봇 자신의 관점이다.
- `y` 좌표는 아래로 갈수록 증가하고 `yVelocity > 0`은 낙하 중이라는 뜻이다.
- 신규 스킬 공개 시 기존 필드는 유지되고 새 필드만 추가될 예정이다.

## 게임 및 대회 진행 규칙

- 한 세트는 10점 선착이다.
- 매치 시작 서브권은 무작위로 정한다.
- 공이 네트를 넘지 않은 채 한 진영에서 연속 5회 접촉하면 그 진영이 실점한다.
- 예선은 3조, 조당 4팀이며 한 경기는 1세트다. 팀당 6경기를 치른다.
- 각 조 1·2위와 조 3위 중 승점·득실차 상위 2팀이 본선에 진출한다.
- 본선은 8강 토너먼트이며 한 경기는 3세트, 2세트 선취 방식이다.
- 세트 시작 후 4분에 앞선 팀이 승리한다. 동점이면 5분까지 골든볼을 진행하고,
  그때까지도 동점이면 무승부다.

API 페이지에는 세트 수가 추후 결정 예정이라는 과거 문구가 남아 있다. 진행 방식을
전담하는 `/guide/rules`에는 예선 단판과 본선 3세트 2선승이 구체적으로 적혀 있으므로,
현재 진행 방식은 규칙 페이지를 우선한다.

## 부정행위

공식 가이드는 다음과 같은 고의적 행위를 부정행위로 본다.

- 매치와 무관한 대량 초기화 연산으로 timeout을 고의 유발하여 시스템을 방해하는 행위
- 브라우저 취약점이나 엔진 버그를 악용하는 행위
- NaN 또는 Infinity 주입으로 판정을 흐트리는 행위
- 게임 코드나 상대 봇 코드를 훔치거나 수정하려는 행위
- 온라인의 기존 다른 봇을 표절하는 행위
- shaims 또는 리온이 배구 코드를 악용하는 행위

의도하지 않은 버그는 부정행위가 아니라고 명시되어 있다.

## 제출 전 확인표

- [ ] 단일 `.js` 또는 `.py` 파일이며 4MB 이하인가?
- [ ] 최상위 `decide(snapshot)`이 있는가?
- [ ] 모든 반환값이 허용 범위에 있는가?
- [ ] 금지 API, 파일 I/O, 네트워크, Worker 생성이 없는가?
- [ ] 정상 tick이 120ms 안에 끝나고 최악의 경우에도 360ms를 넘지 않는가?
- [ ] 진영 방향을 `side`에 맞게 처리하는가?
- [ ] tick 간격 계산에 `config.tickFrameGroupSize`를 사용하는가?
- [ ] 로그가 매 tick 무제한으로 출력되지 않는가?
- [ ] 5회 연속 접촉으로 인한 실점 가능성을 점검했는가?
- [ ] 부정행위로 해석될 의도적인 exploit 또는 방해 로직이 없는가?
