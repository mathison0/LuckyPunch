> **v5·v6을 맞대결 60%로 이긴다** — 동전던지기가 아닌 최초의 진짜 우위

## 한 줄 요약

두 가지가 들어갔고, **가치는 첫 번째가 대부분**이다.

1. **공중 낙하점 버그 수정** — v5·v6에 잠복하던 진짜 버그. 이것만으로 맞대결 60%.
2. **시간 게이트 와리가리** — 상대의 조기 조준을 교란하는 비용 0의 보험.

## 1. 공중 낙하점 버그 (진짜 개선)

### 증상

v5·v6은 공중에서 **이 공을 칠 수 없다고 판단하면**(`contact < 0`) 그냥 공을 쫓았다.

```js
var xToBall = trackX(traj[Math.min(lag, landIdx)].x, myX);   // 공의 2프레임 뒤 위치
...
return { x: xToBall, y: 0, hit: 0 };   // ← 여기로 떨어진다
```

그런데 **빠른 반격은 나를 지나쳐 등 뒤에 떨어진다.** 공을 향해 걷는 게 곧 낙하점에서
멀어지는 것이 된다.

프레임 트레이스로 잡은 실제 장면: **반격 낙하점이 `x=36`인데 `x=184`까지 걸어갔다.**
코트 반대편 끝이다. 절대 못 돌아온다.

### 왜 오래 살아남았나

v5에서 이미 관련 코드를 건드렸었다. `DEF_AIR` 실험 당시 "상대 코트로 떠나가는 공은
쫓지 않는다"는 처리를 넣었다가 순손해라 껐는데, **그때 본 건 "떠나가는 공"이었고
진짜 문제는 "내 쪽으로 오는데 나를 지나치는 공"이었다.** 조건이 `!landsOnMySide`라
정확히 반대 케이스만 잡고 있었다.

### 수정

```js
if (contact < 0 && landsOnMySide) {
  var towardNetAir = isLeft ? 1 : -1;
  var recvAir = clamp(landX - towardNetAir * RECEIVE_OFFSET, reachMin, reachMax);
  return { x: walkTo(recvAir, myX), y: 0, hit: 0 };   // 낙하점 옆으로 즉시
}
```

공중이어도 **못 칠 공이면 착지 후 받을 자리로 곧장 걷는다.** 공을 쫓지 않는다.

`RECEIVE_OFFSET`을 그대로 쓰는 게 포인트다 — v1에서 정한 그 값이다. 낙하점 정중앙에
서면 몸통 리턴 `vx`가 0이 되어 공이 되떨어지므로, 네트 반대쪽으로 12px 물러선다.

**이 수정 하나로 v5·v6을 60%로 이긴다.**

## 2. 시간 게이트 와리가리 (비용 0의 보험)

### 동기 — v6가 증명한 위협

v6는 "상대 위치·속도를 외삽해 있을 곳의 반대편을 노린다"를 구현했다. 그렇다면
**우리도 당할 수 있다.** 그리고 우리 수비 대기는 maximin 위치에 서서 **정지**하는데,
**정지는 속도 0으로 완벽하게 예측된다.** 가장 읽기 쉬운 표적이다.

### 구현 — `jinkAround`

```js
function jinkAround(targetX, myX, lo, hi, amp) {
  if (amp < PLAYER_SPEED)      return walkTo(targetX, myX);   // 여유 없음 → 정밀 수비
  if (Math.abs(dx) > amp)      return dx > 0 ? 1 : -1;        // 아직 멀다 → 직행

  if (tickCounter >= oscFlipAt) {                             // 무작위 시점에 방향 재추첨
    oscDir   = Math.random() < 0.5 ? -1 : 1;
    oscFlipAt = tickCounter + OSC_MIN_TICKS
              + Math.floor(Math.random() * (OSC_RAND_TICKS + 1));
  }
  // 진폭·코트 경계에서 반사
  ...
  return oscDir;
}
```

설계 원칙 셋:

- **커버리지 우선.** maximin 위치까지는 **직행**한다. 도착한 뒤에만 흔든다.
- **항상 `|속도| = 6`.** 정지하지 않으므로 속도 외삽 공격에 최대 `6 × 외삽구간`px의
  오차를 강제한다.
- **`Math.random`으로 방향 전환.** 상대가 우리 코드를 그대로 시뮬레이션해도 못 맞춘다.

### 게이트 두 개가 직렬로 걸린다

`planDefenseTarget()` 안에 있다.

```js
if (plan.contactIdx > JINK_SAFE_FRAMES) {   // ① 시간 게이트 (22프레임)
  out.amp = clamp(-plan.worst - 6, 0, OSC_AMP);   // ② 슬랙 게이트
} else {
  out.amp = 0;                              // 접촉 임박 → 정확 수렴
}
```

**상대 접촉이 22프레임 이상 남았을 때만 흔들고**(①), 통과했으면 **maximin 최악 마진의
여유(`-worst`)만큼만** 진폭을 준다(②). 접촉이 다가오면 0으로 죽이고 maximin 위치에
정확히 수렴한다.

> 아래 표는 **슬랙 게이트 단독이 실패**했다고 적고 있는데, 코드에는 그게 남아 있다.
> 모순이 아니다 — 슬랙은 **단독 판정자로는 실패**했고, **시간 게이트 뒤의 진폭
> 조절기로는** 살아남았다. 순서가 전부다.

## 와리가리에서 배운 것 (가장 값진 교훈)

세 번 시도해서 두 번 재앙이었다.

| 시도 | 결과 |
|---|---|
| **상시 진동** | **vs v5 0%** — 완전한 재앙 |
| **슬랙 게이트** (`-worst` 여유만큼 진동) | 실패 |
| **시간 게이트** (접촉 22프레임 전까지만) | 무해 (ON/OFF 성적 동일) |

### 왜 상시 진동이 0%였나

집안 랠리는 **20px 미만의 칼끝 마진**으로 갈린다. ±20px 진동 변위가 그 마진을 전부
집어삼켜 **실점으로 바꿨다.**

### 왜 슬랙 게이트도 실패했나

이게 더 미묘하다. `-worst`(maximin 최악 마진의 여유)만큼 흔들면 "커버리지를 잃지 않는
범위 내에서만 흔드는" 게 될 줄 알았다. 그런데 **슬랙은 "낙하점까지 걸어가서 몸으로
받는다"는 모델의 여유**인데, **실제 수비는 점프 요격**이다. 모델과 실제가 달라서
그 여유가 **허수**였다.

### 결론

> **타격 순간의 위치가 전부인 이 게임에서, 마지막 순간까지 위치를 숨기는 것은
> 반드시 수비력을 지불한다.**

무해했던 건 **시간 게이트 하나뿐**이다. "충분히 이른 시점에만 흔들고, 결정적 순간엔
정확히 선다"가 유일하게 공짜인 조합이었다.

## 신규 파라미터

| 이름 | 값 | 의미 |
|---|---|---|
| `OSC_AMP` | 20 | 진동 폭 (px) |
| `JINK_SAFE_FRAMES` | 22 | 상대 접촉이 이보다 멀 때만 진동 |
| `OSC_MIN_TICKS` | 2 | 방향 유지 최소 tick |
| `OSC_RAND_TICKS` | 4 | 추가로 0~4 tick 무작위 유지 |

## 성적 — 숫자 읽는 법에 함정이 있다

lag1, 지터 {0, 8}, 상대당 48게임:

| | vs AI | vs v1 | vs v2 | vs v3 | vs v4 | vs v5 | vs v6 |
|---|---|---|---|---|---|---|---|
| v5 | 83% | 83% | 85% | 100% | 100% | — | — |
| v6 | 90% | 94% | 83% | 98% | 98% | 50% | — |
| **v7** | 83% | 100% | 81% | 98% | 98% | **60%** | **60%** |

> ⚠️ **"v7 풀 종합 82.9% vs v6 92.6%"를 그대로 비교하면 안 된다.**
> 두 수치의 **모집단이 다르다.** v6의 92.6%는 AI·v1~v4 **5종** 평균이고,
> v7의 82.9%는 거기에 v5·v6을 더한 **7종** 평균이다. 강한 집안 상대 둘이
> 추가됐으니 평균이 내려가는 건 당연하다.
>
> **공통 풀(AI·v1~v4)로 맞추면:**
>
> | | 공통 풀 평균 | 맞대결 |
> |---|---|---|
> | v5 | 90.2% | — |
> | v6 | 92.6% | vs v5 50% |
> | **v7** | **92.0%** | **vs v5 60% · vs v6 60%** |
>
> 즉 **v7은 v6과 외부 상대 성적이 동급이면서, 집안 맞대결만 이긴다.** 이게 정확한 요약이다.

기타 실측:

- `decide` 실행시간: **지상 공격 1.7ms / 수비 0.19ms** (예산 120ms의 1/70)
- 브라우저: 로드 정상, 타임아웃 0, v5와 8:10 접전 (60% 승률이면 정상 범위)
- 브라우저 실전 시리즈 (빠른 속도, 진영 교대 8게임): v6 5승 3패 — 동급 확인
