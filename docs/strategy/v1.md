# v1 — 수비 베이스라인

> `src/code-here/LuckyPunch_v1.js` · 81줄 · 오프라인 종합 승률 **21.9%**

## 한 줄 요약

파워히트를 전혀 쓰지 않고 `expectedLandingPointX`만 쫓아가 몸으로 받아 넘기는 최소 봇.
**이기려고 만든 게 아니라 "파이프라인이 돈다"를 확인하려고 만든 것이다.**

## 목적

`decide` 계약, 좌표계, 봇 설정 UI, 재빌드 루틴이 실제로 동작하는지 검증하는 스캐폴딩.
이 단계에서 확인한 것:

- 파일 하나에 최상위 `decide` 함수만 있으면 로드된다 (export 불필요)
- `side`가 `LEFT`/`RIGHT`로 들어오고, 좌표는 원작 픽셀 그대로다 (정규화 없음)
- y축이 **아래로 갈수록 증가**한다 — 최고점일수록 y가 작다
- 반환값이 그 tick(3프레임 = 120ms) 동안의 조작이 된다

## 로직

세 줄로 끝난다.

### 1. 좌우 위치잡기

```js
var towardNet = s.side === 'RIGHT' ? -1 : 1;   // 방향 하드코딩 금지
var landingX  = s.ball.expectedLandingPointX;  // 매 tick 새로 읽는다 (캐시 금지)
```

- 낙하지점이 **내 코트 안**이면 → `landingX - towardNet * RECEIVE_OFFSET` 로 이동
- 아니면 → 내 코트 중앙에서 대기

`RECEIVE_OFFSET = 12`가 핵심이다. 낙하지점 **정중앙**에 서면 공이 몸 위로 곧장 튀어
다시 내 코트에 떨어진다. 몸통 리턴의 `vx = (공x - 플레이어x) / 3`이 0이 되기 때문.
살짝 네트 반대쪽에 서서 몸의 "네트 쪽 면"으로 받아야 공이 넘어간다.

### 2. 데드밴드

```js
if (Math.abs(dx) > WALK_DEADBAND) x = dx > 0 ? 1 : -1;   // WALK_DEADBAND = 6
```

반응 지연이 구조적으로 ~1 tick(120ms) 있다. 데드밴드가 없으면 목표를 지나쳤다가
되돌아오기를 반복하며 **좌우 진동**이 생긴다. 6px는 그걸 억제하는 최소값이다.

### 3. 엄격한 점프

네 조건이 **전부** 맞을 때만 `y = -1`:

| 조건 | 값 | 이유 |
|---|---|---|
| `self.state === 0` | 지상 | 점프는 지상에서만 발동한다 |
| `\|ball.x - self.x\| < 32` | x 정렬 | 히트박스 반폭 |
| `\|ball.xVelocity\| < 5` | 옆속도 느림 | 빠르면 점프해도 놓친다 |
| `ball.y < 150` | 충분히 높음 | 낮으면 서서도 받힌다 |
| `ball.yVelocity > 0` | 내려오는 중 | |

플레이어 히트박스가 상하 ±32px라 어지간한 높이는 **서서도 받힌다.**
어설프게 뛰면 33프레임 착지하는 사이에 공이 지나가므로, 점프는 아낀다.

## 왜 21.9%인가

`hit: 0`을 반환한다 — **파워히트를 한 번도 안 친다.**
몸통 리턴은 `vy = -max(|공의 vy|, 15)`라 항상 높이 뜨는 느린 공이고,
`vx`도 최대 ±10 남짓이라 상대가 여유롭게 따라간다. 실점을 늦출 뿐 점수를 못 낸다.

게다가 가이드가 명시했다: **"수비형은 통하지 않을 가능성이 높다. 매서운 공격을 시도하라."**

→ v2에서 공격을 얹는다.

## v2가 고친 것

- `expectedLandingPointX`(엔진이 준 값) 대신 **직접 궤적을 프레임 단위로 예측**
- 점프 타이밍을 역산해서 공을 **공중에서 만난다**
- 접촉 순간 파워히트 6조합을 전부 시뮬레이션해서 최선을 고른다
