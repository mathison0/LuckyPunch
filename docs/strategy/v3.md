## 변경 ① — 요격 회피 평가 (`evaluateShot`)

### 문제

v2의 점수는 `|낙하x - 상대x| - 6 × 도달프레임` 하나뿐이었다. **낙하 순간만 본다.**

그런데 **평평한 스매시(`y=0`)** 는 `vy`가 정확히 0이라 상대 코트를 **타격 높이 그대로
천천히 가로지른다.** 낙하지점은 벽 근처라 멀어 보이지만, 지나가는 도중 아무 데서나
상대가 손을 댈 수 있다. 자기대전에서 **서브를 넣은 쪽이 오히려 지는** 일이 잦았던 원인.

### 해결

낙하 순간이 아니라 **비행하는 모든 프레임**에서 상대가 닿을 수 있는지 본다.

```js
for (t = 1; t <= SIM_LIMIT; t++) {
  stepBall(b);
  // 상대 코트 안 && 상대가 점프해서 닿을 높이인가
  //   점프 정점 y=108, 히트박스 ±32 → y < 76 이면 못 닿는다
  if (inOppCourt && b.y >= JUMP_APEX_Y - PLAYER_HALF) {
    canLo = max(oppReachMin, oppX - 6*t);
    canHi = min(oppReachMax, oppX + 6*t);
    shortfall = (b.x가 [canLo, canHi] 밖이면 그 거리, 아니면 0);
    margin = shortfall - 32;        // 양수 = 못 닿음
    easiest = min(easiest, margin); // 상대에게 가장 쉬운 순간이 이 공격의 품질
  }
}
```

`margin`의 **최솟값**(= 상대에게 가장 쉬운 순간)이 이 공격의 품질이다.
양수면 상대는 **어느 시점에도** 공에 닿을 수 없다.

### 두 항의 혼합

```js
score = (|낙하x - 상대x| - 6*프레임)  +  MARGIN_WEIGHT * margin
        └────── 낙하 항 ──────┘         └── 요격 항 ──┘
```

`MARGIN_WEIGHT = 1`. **요격 항만 쓰면 안 된다** — 상대가 타이밍까지 완벽히 맞춘다고
가정하는 셈이라 지나치게 비관적이고, 결국 아무도 안 건드릴 **느린 아치만** 고르게 된다.
`MARGIN_WEIGHT = 0`이면 정확히 v2와 같아진다.

## 변경 ② — 정지 구간 감지 (실전 승패를 가른 수정)

득점 후 `afterEndOfRound`(5프레임) → `beforeStartOfNextRound`(30프레임), 첫 랠리는
`startOfNewGame`(71프레임) 동안 **physics가 돌지 않는다.** 그런데 `decide`는 계속 호출된다.

v2는 그 얼어붙은 스냅샷을 보고 점프해서 **서브를 통째로 놓쳤다.**

```js
var frozen = (s.ball.x === prevBallX && s.ball.y === prevBallY) || s.ball.y === 0;
prevBallX = s.ball.x;
prevBallY = s.ball.y;

var action = think(s, prevY);           // 평소대로 판단하고
if (frozen) return { x: action.x, y: 0, hit: 0 };   // y·hit만 죽인다
return action;
```

**좌우 이동은 남긴다.** 정지 중엔 어차피 반영되지 않지만, 랠리가 시작되는 첫 프레임부터
곧바로 걸어갈 수 있어 오히려 이득이다.

> 이 한 가지 때문에 오프라인 승률 100%인 봇이 브라우저에서 5-10으로 졌다.
> **오프라인 하네스도 이 정지 구간을 재현해야 브라우저와 결과가 맞는다.**

## v3의 구조 (전체)

```
decide(s)
 ├─ 정지 구간 감지 → frozen 이면 y·hit 무력화
 └─ think(s)
     ├─ 공중 (state 1·2)
     │   ├─ jumpPhase()로 내 점프 위상 역산 (올라가는 중/내려오는 중 구분)
     │   ├─ 접촉 프레임 탐색 (높이 ±32, 좌우 도달 가능)
     │   └─ 접촉 임박 → chooseHit() 7조합 평가 → 파워히트
     ├─ 지상 · 공이 상대 쪽 → 코트 중앙 대기
     ├─ 지상 · 공이 내 쪽  → 점프 스매시 계획 (가장 이른 접촉 고정)
     └─ 계획 실패 → 몸통 리턴 / 다이빙
```

## 남은 한계

1. **접촉 시점이 "가장 이른 것"으로 고정.**
   조금 늦게 쳐서 공이 네트에 가까워졌을 때 급강하를 꽂는 편이 나은 경우를 놓친다.
   → v4가 후보를 비교한다.

2. **수비가 코트 중앙 고정.**
   공이 상대 쪽에 있으면 그냥 중앙에서 기다린다. 상대가 어디를 노릴지 전혀 예측하지 않는다.
   → v5가 maximin 예측 수비로 고친다.

## 참고 — v3과 v4는 실측 지연에서 완전히 같다

v4는 공짜 보험이고, 실질적 도약은 v5다.
