# v4 — 접촉 시점 최적화 (+ 다단 세팅 실험·기각)

> `src/code-here/LuckyPunch_v04.js` · 653줄 · 오프라인 종합 승률 **83.3%**
> **실측 지연(1)에서 v3와 동작이 완전히 동일하다.** 차이는 지연이 커질 때만 난다.

## 한 줄 요약

두 가지를 시도했다.
① **접촉 시점 선택** — 채택. 후보를 여러 개 모아 비교한다.
② **다단 세팅** (띄우고 스매시) — **기각.** 물리적으로 성립하지 않는다는 걸 측정으로 확인.

종합 승률이 93.1% → 83.3%로 떨어져 보이지만, 이건 **세팅을 켠 채 잰 구간이 섞인 값**이고
세팅을 끄면 실측 지연에서 v3와 동일하다. v4의 진짜 가치는 **지연이 커질 때의 보험**이다.

## 채택 ① — 접촉 시점 후보 비교

### 문제

v3는 "칠 수 있는 **가장 이른 접촉**"에 고정돼 있었다. 이른 접촉일수록 공이 높아 각도는
좋지만, 조금 늦게 쳐서 공이 **네트에 더 가까워졌을 때** 급강하를 꽂는 편이 나은 경우가 있다.
(→ [급강하가 성립하는 조건](#급강하-스매시가-성립하는-조건) 참고)

### 해결

`findJumpContacts(...)` 가 **최대 6개**(`CONTACT_CANDIDATES`) 후보를 모으고, 각각에 대해
`chooseHit`을 돌려 점수를 비교한다.

```js
// 이른 접촉이 기본. 늦추는 건 확실히 더 좋을 때만.
if (direct === null || cs > directScore + CONTACT_GAIN) { direct = cand; }
```

### `CONTACT_GAIN`은 지연 환경에 거는 도박이다

늦은 접촉일수록 예측 오차에 취약하다 (그 사이 상대가 뭘 할지 모른다).

| `CONTACT_GAIN` | 실측 지연 1 | 지연 3 |
|---|---|---|
| 30 (적극적으로 늦춤) | v3 대비 **75%** | **36%** — 무너진다 |
| **60 (채택)** | v3와 동일 | 전 구간 중립~우세 |

30은 실측 환경에서 강하지만 타이밍이 달라지면 붕괴한다. **중립값 60**으로 뒀다.

### `headStart` — 시간 낭비를 자동으로 감점

`evaluateShot`에 인자가 하나 늘었다.

```js
reach = PLAYER_SPEED * (t + headStart);   // 상대가 이미 움직일 수 있었던 프레임 수
```

내가 공격을 미루면 그만큼 상대가 자리를 잡는다. 이걸 상대의 도달 범위에 더해주면
**"시간만 낭비하는 선택"이 자동으로 걸러진다.** 세팅 평가의 핵심 장치이기도 하다.

## 기각 ② — 다단 세팅 (`MAX_SET_TOUCHES = 0`)

> **이 전략은 다시 제안하지 말 것.** 측정 결과 순손해였고, 이유가 물리에 있다.

### 아이디어

1터치로 몸통 리턴해 내 코트에 띄우고, 2터치로 네트 앞에서 급강하를 꽂는다.
`planSet()`이 서는 위치(offset)를 3px 간격으로 바꿔가며 **2수 앞을 시뮬레이션**한다.

### 왜 안 되는가

<a name="급강하-스매시가-성립하는-조건"></a>
**급강하 스매시(`y=1`)는 네트에서 약 35px 안에서 쳐야만 넘어간다.**

공이 네트 기둥 구간(x 191~241)을 지날 때 `y <= 176`이어야 통과한다. 접촉 높이 y=84,
`|x|=1`(vx=±20), vy=30이면 y가 176을 넘기 전까지 **2프레임**밖에 못 간다.

RIGHT 기준 접촉 x별 착지 (직접 계측):

| 접촉 x | `y=1` 급강하 | `y=0` 평평 |
|---|---|---|
| 376 | 276 **자기 코트** ✗ | 16 (19프레임) ✓ |
| 300 | 260 **네트 걸림** ✗ | 60 ✓ |
| 260 | 300 ✗ | 100 ✓ |
| **240** | **140 (6프레임)** ✓ | 120 ✓ |

**깊은 곳에선 평평한 스매시밖에 답이 없고, 네트 앞에서만 킬샷이 나온다.**

그런데 몸통 세팅은 `vy = -max(|공vy|, 15)`라 **체공이 최소 30프레임**, 천장(`y<0`)
판정까지 걸리면 40프레임이다. 그 시간 동안 네트 쪽으로 의미 있게 옮길 `vx`(≈3 이상)를
주면 공이 그대로 네트를 넘어가거나 벽에 부딪힌다.

**결론: 좁은 창(네트 35px)에 공을 못 놓으면서 상대에게 30~40프레임 = 200px 이동거리를 그냥 준다.**

### 측정

v4 vs v3 미러 20세트. 세팅 임계값(`SET_MIN_GAIN`)을 낮춰 자주 할수록 실측 지연 1에서
승률이 **30%까지** 떨어졌다. 세팅을 끄면 정확히 v3와 같아졌다.

### 코드는 남겨뒀다

`MAX_SET_TOUCHES = 1`로 올리면 켜진다. **대회 당일 스킬로 물리가 바뀌면 재검토 가치가 있다.**

## 부수적으로 추가된 것 — 점유 접촉 카운터

> 규칙: **한 진영 연속 5회 접촉 시 실점** (원작에 없는 대회 규칙)

```js
if (onMySide !== prevOnMySide) possessionTouches = 0;         // 네트를 넘었다 = 점유 교체
if (onMySide && prevBallVy > 0 && s.ball.yVelocity < 0) possessionTouches++;  // 떨어지다 뜸 = 내가 댐
```

세팅이 OFF인 지금은 실질적으로 쓰이지 않지만, 세팅을 다시 켤 때 필요한 안전장치다.

## 신규 파라미터

| 이름 | 값 | 의미 |
|---|---|---|
| `CONTACT_CANDIDATES` | 6 | 접촉 시점 후보 개수 |
| `CONTACT_GAIN` | 60 | 이만큼 더 좋아야 접촉을 늦춘다 |
| `MAX_SET_TOUCHES` | **0** | 세팅 OFF (기각) |
| `SET_MIN_GAIN` | 25 | 세팅이 직접 공격보다 이만큼 나아야 |
| `SET_OFFSET_STEP` | 3 | 세팅 위치 후보 간격 (`vx`는 3px마다 1씩 바뀐다) |
